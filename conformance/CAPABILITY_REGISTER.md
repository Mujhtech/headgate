# Capability register

Structured attempt logging extension: debug/info/warn/error, capture-time
timestamps, bounded scalar fields, a job-scoped Go slog handler and Rust logger, and UI
level filtering. Preserves the string-array store port with a versioned entry codec and
legacy info-level display. This does not add streaming or change outcome persistence.
Runtime capture, concurrent bounds, legacy decoding, and fenced persistence through all
six language/backend combinations are tested; see the Per-attempt logs evidence block.

The gaps in this design were found reactively — one per review round — which is a process
failure, not bad luck. This file is the fix: the full capability surface of a job queue,
enumerated once, with an honest status for each. **Nothing gets called complete without a
line here.**

Status: ✅ designed · 🔶 partial · ❌ missing · ⏸ deliberately deferred (§12)

**Precedence rule:** when this register and `state_machine.yaml` disagree, **the table
wins** — the register row is the stale artifact and gets corrected, not the transition.
(Found the hard way: "ephemeral jobs" sat here as ❌ while the table already mandated
`success → deleted when retention_ms == 0`.)

Source material for every round: **[`../docs/README.md`](../docs/README.md)** — River,
Oban, Sidekiq, asynq, and apalis enumerated feature by feature.

**Round 3.** asynq (~200 API items) and apalis (18 crates, read from source — its docs
disagree with its code) added another 18. The pattern held: River's enumeration surfaced
*feature* gaps, these two surfaced *operational* ones — connection ownership, deployment
topologies, idle polling, and the complete absence of a CLI. Different competitors fail
you in different directions, which is the argument for enumerating all of them.

**Round 2.** The first pass was thematic — categories I thought of. A full enumeration of
River + River Pro (246 features) then found sixteen more, several of which the thematic
sweep could not have caught because they are not "capabilities" so much as adoption
requirements. That is the argument for enumerating a competitor exhaustively rather than
reasoning from categories: the categories are yours, and the gaps are in the ones you did
not think to name.

## Round 32u — IDENTITY IS UPSTREAM; THE ENQUEUE VERDICT IS NOT

The eighth explicit gap is now a producer boundary rather than another store policy.

hook receives the source, an identity established by the embedding application, and the
complete envelope. Headgate does not authenticate, parse an identity header, or prescribe
roles. The compatibility default is stated rather than accidental: no configured hook
means allow-all, while an installed hook decides whether anonymous callers are allowed.

Authorization finishes before any durable call. A mixed batch with an allowed first job
and forbidden second job writes neither, and transactional enqueue makes its decision

structured 403 in Rust and Go. This prevents the two less-obvious bypasses: installing a
future forbidden schedule, and manually firing a pre-existing one. Existing schedules
remain trusted durable configuration and must be paused or deleted explicitly when policy
changes.

request hook — while Oban Web resolves identity separately and has granular
`insert_jobs` permission. Headgate follows those shapes without copying either role
model. `docs/enqueue-authorization.md` records the trust boundary: application code that

store-health verdict.

## Round 32ab — A CHILD FUTURE IS PART OF THE ATTEMPT, NOT A DETACHED PROCESS

The fifteenth explicit gap carries apalis's strongest shutdown detail into both runtimes:
work deliberately spawned inside a handler can now remain owned by that attempt. Rust's
tracker is structural (`JoinSet` abort); Go's is context-cooperative, because the language
cannot kill a goroutine safely. Both close registration when the handler returns and wait
before success, so “handler returned” can no longer race “background side effect finished.”

The failure paths are equally important. Child error cancels siblings and fails the
attempt. Handler error/timeout cancels children before ack. Lease loss cancels immediately
and never acks from the old fence. The Rust proof deliberately makes the child retain its

the explicit abort breaks that cycle. The Go proof requires the exact cancellation error.

## Round 32ae — A RETRY IS NOT A DEATH ALERT

## Round 32af — CANCELLATION IS A REQUEST; THE FENCE IS AUTHORITY

The nineteenth explicit gap reports the one case structured task ownership cannot solve:
user work that ignores cancellation. A timer from job start would mislabel legitimate
long-running work, so the grace period starts only when the attempt timeout elapses or
lease-loss/forced-shutdown cancellation is requested. Handler and registered tracked work
are one liveness unit.

The implementation follows each language's real execution model. Rust places guards
inside the isolated handler task and every tracked future; watching the abortable outer
task would miss a CPU-bound child still occupying another executor thread. Go watches the
attempt context until handler return and tracked-task join, because goroutines cannot be
preempted safely. Cooperative controls emit nothing; stubborn tracked children emit once
after 20ms and only then are released.

Notification does not restore authority. Each stubborn child deliberately submits a
success ack with the old lease after its callback; both Store wrappers reject the fence,
leave the durable row `running`, and record no attempt. Removing the post-grace liveness
check made the cooperative control fire in both languages. The Go proof also exposed and
fixed an ordering bug: canceled work returning nil reached the success arm before the
cancellation arm, relying on the Store fence to reject an ack the runtime should never
attempt.

replacement slot; capacity remains explicit fleet policy. `docs/stuck-job-handlers.md`

## Round 32ag — A SLOW LISTENER DOES NOT GET TO HOLD THE ACK PATH
