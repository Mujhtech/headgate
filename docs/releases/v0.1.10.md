# v0.1.10 release notes

## SQLite stores for Rust and Go

- Added first-class `headgate-sqlite` and `headgatesqlite` packages with the same
  admission, lifecycle, policy, inspection, and transactional capability contracts as
  the other SQL stores.
- SQLite uses store-owned time, atomic claims and leases, fenced lifecycle operations,
  work-conserving fairness, rate and concurrency policies, quarantine handling, and
  durable workflow state.
- Added SQLite conformance harnesses, migration parity checks, test inventory coverage,
  backend documentation, and release packaging for both language ecosystems.

## Store and operations parity

- Added compile-time store capability assertions so supported operations cannot drift
  silently between drivers.
- Completed output inspection and trace-context behavior across stores and expanded the
  shared Go and Rust conformance evidence.
- Improved workflow state and traffic metrics exposed by the control API and console.

## Embedded console reliability

- Added authorized encrypted-payload reveal support without changing the safe default
  that omits job payloads.
- Fixed server/client markup mismatches that caused React error 418 in production builds.
- Fixed embedded favicon URLs so Docker deployments no longer expose build-machine
  `file://` paths.
- Hardened server-sent event streaming so idle Docker connections retain a rolling write
  deadline instead of ending with incomplete chunked encoding.

## Upgrade notes

- Upgrade the Headgate Rust crates and Go modules together to v0.1.10.
- Existing PostgreSQL, MySQL, and Redis installations require no database migration for
  this release.
- SQLite is a new optional backend. New SQLite deployments initialize its versioned
  schema through the normal migration path.
